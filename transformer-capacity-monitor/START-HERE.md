# Start here: Transformer Capacity Monitor (Tompkins County)

A fixed-rules tool that logs transformer loads, checks load stability with control charts, measures
capacity headroom against each transformer's rated maximum, applies the heat-pump growth forecast,
and prepares a report that a named grid-planning reviewer approves. No AI is used. It never changes
equipment or operating settings.

## Everyday use (three steps)

1. **Open the tool.** Double-click `Start Capacity Monitor.command` (or run `./scripts/start_app.sh` and
   `./scripts/start_airflow.sh`). Your browser opens http://127.0.0.1:5055 on the **Map**: every transformer
   as a dot, green for within limits and red for needing review; click a red dot for its numbers and
   **Open full review**. The **Heatmap** link shows where load sits hour by hour (recorded) or by month (a labeled model). Scheduled runs happen on their own on Monday, Wednesday and Friday at 06:00; to run one yourself,
   pick a period end date at the top of the Map and press **Run now**. The **Dashboard** shows the scheduler, alerts and run history.
2. **Review the exceptions.** Open the period, press **Review** on each flagged transformer, read the
   checklist beside the chart and source readings, then choose **Approve conclusion**, **Request changes**
   or **Reject** (with a note). One case at a time; nothing is batch-approved.
3. **Approve and finalize the report.** When every exception has a disposition, press
   **Approve and finalize report**. The final report (HTML, Markdown, JSON) is in
   `data/reports/<period end>/` and linked on the period page. Share it with the grid-planning team.

## Reopen, stop, recover

- **Reopen:** http://127.0.0.1:5055 while the tool is running; otherwise double-click the Start launcher again.
- **Stop:** double-click `Stop Capacity Monitor.command` (or `./scripts/stop.sh`).
- **Pause scheduled runs:** the **Pause scheduled runs** button on the dashboard (Resume to continue).
- **A run failed:** the dashboard and the Alerts page show the run, the step and the reason (for
  example a missing feed or a boundary file for the wrong period). Fix the feed in `data/feeds/` and
  press **Run now** for the same period end date; the rerun replaces that period's draft.
- **Something looks stuck:** `./scripts/status.sh` shows what is running; `./scripts/stop.sh` then the
  Start launcher restarts everything. Logs are in `logs/`.

## Feeding it real data

The tool reads four files from `data/feeds/` (columns are listed on the Setup page):
`readings.csv`, `assets.csv`, `boundaries.geojson`, `heat_pump_forecast.csv`.
The files there now are **synthetic sample data** for 500 made-up transformers, generated by `scripts/make_synthetic_data.py` (the readings file is not kept in git; setup regenerates it),
and every report built from them is sample output. Replace them with exports from your meter,
asset, GIS and forecast systems, keep the same columns, and run a period.

Thresholds (Cpk review level, forecast margin, chart rules, schedule) live in `rules/playbook.json`
and `rules/decision-table.csv`; record who approved any change.
